# 仕組みとアラートの読み方・誤検知への対処

HomeWatch の2つの検知ツール（Windows 監視・ネットワーク監視）が「何を見て」「どう知らせ」「誤検知に
どう対処するか」をまとめます。

## 共通の考え方：ベースライン方式
「導入時の正常な状態」を **ベースライン**として記録し、以後はそれとの **差分（＝新しく増えたもの）** を
怪しいと見なします。だから **導入は、感染していない確証がある状態で**行うのが理想です。
正規の変更（新しいアプリ・新しい端末）が増えたら、ベースライン/既知リストを更新して取り込みます。

## A. Windows 監視ツール（`windows/`）
タスクスケジューラが15分ごとに `Invoke-HomeWatchScan.ps1` を実行します。データ収集はこのスクリプトが行い、
判定は `modules/HomeWatch.psm1` の関数が担います。

### 何を見るか（検知カテゴリ）
| カテゴリ | 検知内容 | 主なデータ源 |
| --- | --- | --- |
| `logon` | ログオン失敗の多発（ブルートフォース）、リモート/RDPログオン、深夜帯ログオン | セキュリティイベント 4625/4624 |
| `account` | 新規ユーザー作成、管理者グループへの追加、ベースラインに無いユーザー | イベント 4720/4728/4732, `Get-LocalUser` |
| `network` | 許可リストに無い待ち受け（Listen）ポート | `Get-NetTCPConnection` |
| `persistence` | 新しい自動起動（スケジュールタスク/Runキー/スタートアップ）＝マルウェア常駐サイン | タスク・レジストリ・スタートアップ |
| `eavesdropping` | 許可リスト外のアプリによる最近のマイク/カメラ使用＝盗聴/盗撮サイン | ConsentStore レジストリ |

### 通知とログ
- 検知すると **画面トースト通知**＋ `%ProgramData%\HomeWatch\homewatch-alerts.log`（1行1件のJSON）に記録。
- 同じ内容のアラートは既定60分は再通知しません（通知疲れ防止）。
- ログ1行の例：
  ```json
  {"Time":"2026-06-10T03:12:00+09:00","Category":"logon","Severity":"alert","Message":"短時間にログオン失敗が 8 回（ブルートフォースの疑い）","Details":{"count":8,"windowMinutes":4.2,"accounts":"admin"}}
  ```

### アラートが出たときの読み方
- **`alert`（赤）**：新規ユーザー作成・管理者追加・ブルートフォース・新規自動起動・許可外マイク使用など、
  心当たりが無ければ侵入/マルウェア/盗聴の可能性。優先して調査。
- **`warning`（黄）**：リモート/RDP・深夜ログオン・未知の待ち受けポートなど、状況次第。自分の操作か確認。
- 心当たりが無い `alert` が出たら：ネットワークから切断 → パスワード変更（別端末から）→
  Defender のフルスキャン → 不審なユーザー/自動起動の除去 → 必要なら専門家へ。

### 誤検知への対処（疲れないために）
- 正規アプリの自動起動が増えた／新しいユーザーを作った → `Update-Baseline.ps1` で取り込む。
- 正規アプリが使う待ち受けポート → `config/homewatch.config.psd1` の `AllowedListeningPorts` に追加。
- 正規の会議アプリ等のマイク/カメラ利用 → `AllowedMicCameraApps` に名前（部分一致）を追加。
- 失敗ログオンの閾値が厳しすぎ/緩すぎる → `FailedLogonThreshold` / `FailedLogonWindowMinutes` を調整。

## B. ネットワーク監視ツール（`network/`）
常時稼働機器（Raspberry Pi 等）で `homewatch-netscan.py` を定期実行します（設定は `../network/deploy.md`）。

### 何を見るか
- 自宅 LAN で **いま通信している端末（MAC アドレス）** を `ip neigh` / `arp -a` / `arp-scan` で取得。
- `known-devices.json`（既知端末リスト）に **無い MAC ＝見覚えのない端末** をアラート。
  - 侵入者の端末、Wi-Fi タダ乗り、知らないうちに増えた IoT 機器などの発見に有効。

### 通知とログ
- `notify-send` があればデスクトップ通知、無ければ標準エラー出力。`homewatch-netscan.log`（JSON Lines）に記録。
- ログ例：
  ```json
  {"time":"2026-06-10T22:05:00+09:00","event":"unknown_device","severity":"alert","mac":"de:ad:be:ef:00:09","ip":"192.168.1.77"}
  ```

### 誤検知への対処
- 出た端末が自分/家族のもの → `known-devices.json` の `devices` に `"MAC": "端末名"` を追記すれば以後出ません。
  （`--init` を再実行すると、その時点の在線端末をまとめて取り込みます。）
- スマホはプライバシー機能で **MAC アドレスをランダム化**することがあります。その端末の Wi-Fi 設定で
  「プライベートアドレス（ランダムMAC）」を固定にするか、出た MAC を登録してください。

## C. 限界と前提（過信しないために）
- これらは **侵入を100%防ぐものではなく、早く気づくための仕組み**です。守りの基本（更新・2FA・強固なパスワード・
  最小権限）と併用して初めて効果が出ます。
- ベースライン取得時にすでに感染していると、その状態を「正常」と覚えてしまいます。導入は清潔な状態で。
- 高度な攻撃はログを消す/検知を避けることがあります。重要な異変は本ツールだけで断定せず、総合的に判断してください。
